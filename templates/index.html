// SALTO DE PÁGINA 01 · ARQUITECTURA WEB

¿Cómo se creó
esta plataforma?

Esta plataforma web interactiva es la representación digital del sistema de gestión de la casa inteligente. Fue construida con una arquitectura moderna de tres capas: backend en Python, base de datos relacional en la nube, y despliegue continuo vía control de versiones.

⚗️
Flask + Python
El backend fue desarrollado con Python 3.12 y el micro-framework Flask. Flask se encarga del ruteo de la aplicación, la lógica de negocio y la comunicación AJAX con el frontend para la conmutación en tiempo real de los estados de cada zona de la casa.
Routes AJAX Jinja2
🐘
PostgreSQL + SQLAlchemy
La persistencia de los datos se maneja con una base de datos relacional PostgreSQL. SQLAlchemy actúa como ORM (Object-Relational Mapper), permitiendo interactuar con la base de datos usando modelos Python sin escribir SQL directo, facilitando el mantenimiento.
ORM Modelos Migraciones
☁️
Render + Neon Tech
Todo el despliegue en producción se realizó en la nube: Render aloja la aplicación Flask y sirve la web al usuario final, mientras que Neon Tech provee la instancia de PostgreSQL serverless en la nube. Ambas plataformas se conectan de forma segura mediante variables de entorno.
Serverless Production SSL
🔗
GitHub · CI/CD
El control de versiones y el flujo de despliegue continuo se gestionan a través de GitHub. Cada push al repositorio principal dispara automáticamente un nuevo despliegue en Render, garantizando que la versión publicada siempre refleje el último estado del código.
Git Flow Auto-Deploy Branches

// SALTO DE PÁGINA 02 · PROYECTO ESCOLAR

Tech House:
Vivienda Inteligente

Proyecto de sexto semestre · Grupo 603 — Diseño, arquitectura y construcción de una maqueta de vivienda inteligente automatizada, integrando circuitos electrónicos, programación con Arduino y una plataforma web de monitoreo en la nube.

🌧️
Sistema 1: Techo Automatizado
El primer sistema implementado físicamente consiste en un techo retráctil controlado por Arduino. Mediante la programación lógica de la placa y un sensor de agua/lluvia, el sistema detecta la presencia de humedad en el ambiente y activa un actuador mecánico para extender o retraer automáticamente el techo de la maqueta, protegiéndola ante cambios climáticos sin intervención humana.
Arduino UNO Sensor de Lluvia Actuador / Servo Control Lógico
💡
Sistema 2: Iluminación Inteligente
El segundo sistema es una red de iluminación LED en paralelo combinada con un detector de oscuridad. El circuito emplea una fotoresistencia (LDR) que varía su resistencia según la intensidad lumínica del entorno. Esta variación es procesada por un circuito con resistencias y transistores que actúan como interruptores, regulando automáticamente la iluminación de la casa según las condiciones ambientales.
LEDs en Paralelo Fotoresistencia (LDR) Transistores Circuito Detector

⚙️ Herramienta / Concepto 🎯 Función en el Proyecto ✅ Recomendación de Uso
Flask
Python Web Framework		 Backend del sistema web: gestión de rutas, lógica de conmutación de zonas y comunicación en tiempo real con el frontend mediante llamadas AJAX. Define todas las credenciales sensibles (contraseña DB, secret key) como variables de entorno y nunca las escribas directamente en el código. Usa os.environ.get().
Arduino + Sensores
Control Físico / Hardware		 Automatización del hardware físico de la maqueta: el sensor de lluvia activa el techo retráctil y la fotoresistencia regula la iluminación LED. Calibra los valores analógicos de tus sensores con lecturas de prueba antes de definir tus umbrales de activación. Los sensores analógicos varían según el modelo y las condiciones de luz.
PostgreSQL
Base de Datos Relacional		 Almacenamiento persistente de los estados de las zonas, logs de eventos y configuraciones del sistema. Alojada en la nube con Neon Tech. Diseña el Diagrama Entidad-Relación (DER) antes de escribir cualquier modelo. Define bien las relaciones (1:N, M:N) para evitar rediseños costosos. Usa migraciones con Flask-Migrate.
Render + Neon Tech
Infraestructura en la nube		 Render aloja la aplicación Flask en producción; Neon Tech provee la instancia PostgreSQL serverless. Conectados mediante la variable de entorno DATABASE_URL. Conecta tu repo de GitHub a Render para activar el despliegue continuo: cada push automáticamente despliega la nueva versión. Verifica que el requirements.txt esté siempre actualizado con pip freeze.

preguntas frecuentes

FAQ

Respuestas a las dudas más comunes sobre la arquitectura técnica del proyecto.

BACKEND ¿Cómo interactúa el servidor Flask con el estado de la casa? ▼
Cuando el usuario hace clic en el botón de una zona, el frontend JavaScript realiza una petición AJAX a la ruta /conmutar/<id> de Flask. Flask busca el registro en PostgreSQL, invierte el valor booleano del campo estado, guarda el cambio y devuelve un JSON con el nuevo estado. El frontend recibe la respuesta y actualiza la interfaz sin recargar la página. Esta arquitectura permite el monitoreo en tiempo real sin interrumpir la experiencia del usuario.
CIRCUITOS ¿Qué ventajas tiene usar circuitos en paralelo para la iluminación? ▼
En un circuito en paralelo, cada LED recibe el mismo voltaje de la fuente, a diferencia de la configuración en serie donde el voltaje se divide. Esto tiene tres ventajas clave para el proyecto: (1) si un LED falla, los demás continúan funcionando; (2) el brillo de cada LED es uniforme e independiente; y (3) se puede encender o apagar una zona específica sin afectar al resto. Aplicando la Ley de Kirchhoff, la corriente total del circuito es la suma de las corrientes individuales de cada ramal.
ARQUITECTURA ¿Por qué se integró Arduino con una base de datos PostgreSQL en la nube? ▼
Arduino controla el hardware físico de forma local y autónoma (responde a sensores en tiempo real sin latencia de red). Sin embargo, para tener un historial persistente, acceso remoto y un panel web de monitoreo, se necesita una capa de software. Flask actúa como puente: puede recibir datos del Arduino por comunicación serial (o WiFi con un módulo ESP), almacenarlos en PostgreSQL (Neon Tech) y mostrarlos en la plataforma web. Esto separa las responsabilidades: Arduino para respuesta física rápida, la nube para persistencia e inteligencia.
SENSORES ¿Cómo funciona la fotoresistencia (LDR) para detectar oscuridad? ▼
Una fotoresistencia (LDR - Light Dependent Resistor) varía su resistencia inversamente proporcional a la cantidad de luz que recibe: en condiciones de oscuridad su resistencia es muy alta (varios MΩ), y con mucha luz baja considerablemente (pocas kΩ). En el circuito del proyecto, la LDR forma un divisor de voltaje con una resistencia fija. Cuando oscurece, la tensión en el punto medio sube lo suficiente para activar la base de un transistor NPN, que actúa como interruptor y enciende el circuito LED, aplicando directamente la Ley de Ohm en el diseño.
DEPLOY ¿Qué es Neon Tech y por qué se usó en lugar de una base de datos local? ▼
Neon Tech es un proveedor de PostgreSQL serverless en la nube. Se eligió en lugar de una base de datos local porque: (1) Render (donde corre Flask) no permite almacenamiento persistente en disco; cada nuevo despliegue reiniciaría una base SQLite local. (2) Neon ofrece una capa gratuita generosa perfecta para proyectos escolares. (3) La conexión se maneja con una única variable de entorno (DATABASE_URL), y SQLAlchemy la usa de forma transparente, igual que si fuera local, sin cambiar una línea de código.
